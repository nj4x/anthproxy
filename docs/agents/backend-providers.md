# Backend-specific behavior

Per-provider transport and mapping quirks.

**Codex**: Accumulate item-level SSE events rather than trusting completed response envelopes. Normalize cached and non-cached input usage into disjoint Anthropic fields before handlers record context, cost, or stats. Streaming startup usage must not override final cumulative usage. Derive prompt cache keys from the nested session ID, with a safe fallback for non-Claude-Code callers.

**Anthropic**: Preserve the required Claude Code system block's ordering when merging beta headers. Keep model-aware payload sanitization in the mapper rather than the router, including capability gates, thinking/context-management compatibility, and folding inline system-role messages into top-level system content.

**Local**: Preserve plain HTTP for local base URLs; do not route them through HTTPS-only helpers.

**Peer**: Dispatches to another anthproxy over its public `/v1/messages`. Transmit the requested model verbatim — no alias resolution and no default substitution; resolving the model is the peer's job. Preserve plain HTTP for `http://` peer URLs, but reject a malformed target rather than defaulting it the way `local` does: a scheme that is not `http`/`https`, a missing host, or an uncastable port must raise, because a silently retargeted request would carry the peer credential in cleartext to a host the operator never named. Any path component of the base URL prefixes the outbound paths, so a peer mounted behind a reverse proxy at `/anthproxy` is reachable. The credential is `X-Anthproxy-Peer-Key`, sent only when `--peer-api-key` is set; never `Authorization: Bearer`, which the receiving instance would absorb as an enterprise OAuth delegation. The peer backend sends this header and never checks one; nothing inbound reads it. Strip `_anthropic_beta` from the outbound body but re-emit its value as an outbound `anthropic-beta` header — the peer speaks native Anthropic and can honour it. `count_tokens` is proxied to the peer with no local-estimate fallback: every non-200, including 404 and connection failures, surfaces as an Anthropic error envelope. Retries use `should_retry()` with an explicit 429 carve-out — a peer 429 always surfaces to the selector, never retried in-backend, with or without `Retry-After`. `from_config` succeeds with an unconfigured `peer_base_url`; the failure is raised at dispatch and names `--peer-base-url`. Startup refuses to boot when the peer target resolves to this instance's own bind address (ADR-0026), gated on `peer` being *enabled*, not merely configured. This adds a boot-time resolution *attempt*, not a boot-time resolution *requirement*: only a positive match is fatal, and a resolution failure logs a warning naming `--peer-base-url` and proceeds, so an outer instance can start before the inner one exists. `five_hour_status` is a constant neutral status (available, weekly unknown) with no network call and no interrogation of the peer — see `docs/agents/concurrency.md` for the ranking and bedrock-ordering consequences. Multi-instance cycles (A→B→A) and self-reference that becomes true after startup are out of scope (SRS-Chaining-007, deferred); no per-request cycle marker is sent and no inbound header is inspected.
