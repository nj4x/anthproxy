# Replace 3-label categorical classifier output with a 0–100 numeric score

The model classifier previously returned one of three categorical labels (`trivial` / `standard` / `deep`) for both the user-prompt and system-prompt classifiers. Labels were translated to scalar scores (`trivial=0.0`, `standard=1.0`, `deep=2.0`) via `_LABEL_SCORES` for the weighted blend (ADR 0010), and the blend result was compared against thresholds on a 0–2 scale to bucket back to a label. This indirection (label → float → blend → threshold → label) limits routing granularity to three steps and requires two separate representations for the same underlying signal.

We replace the categorical label output with a plain integer on a 0–100 scale for **both** classifiers (user-prompt and system-prompt). The classifier system prompts are updated to instruct the LLM to reply with EXACTLY one integer from 0 to 100 and nothing else. The weighted blend and tier thresholds operate directly on the 0–100 integers, eliminating the `_LABEL_SCORES` translation layer entirely.

## Considered Options

**Keep 3-label output, add confidence only:** Simpler, no parser changes, backward-compatible. Rejected because it provides no additional routing granularity; a task at 34/100 and a task at 65/100 still map identically to `standard`. The point of this change is to distinguish within tiers.

**JSON numeric output (always):** Consistent with the confidence-bump path; single parser. Rejected because it requires a larger token budget and introduces JSON fragility for the common case where confidence is not needed. The existing plain-number design (one token) is more robust.

**Add a fourth tier:** Adding `deep-plus` or similar. Rejected because it still requires label-to-number mapping and does not generalize. Numeric output is strictly more expressive.

## Consequences

1. **Parser:** `parse_classifier_score()` is added alongside the existing `parse_classifier_label()`. It extracts text from content blocks (skipping `thinking`/`redacted_thinking`), strips whitespace, then extracts the first contiguous digit sequence via `\d+`; if no digit sequence is found, or if `re.findall(r'\d+', text)` yields more than one match, it returns `None` (this handles both `'42/100'` and `'42 42'` consistently, regardless of whether the values are equal). The extracted integer is validated to lie in `[0, 100]`; out-of-range values also return `None`. The return type is `int` in `[0, 100]` on success, `None` on any failure. The weighted blend result (`weight × int + weight × int`) is a `float`. `parse_classifier_label()` is retained unchanged for rules mode and `_VALID_LABELS` bookkeeping. When `parse_classifier_score()` returns `None` on the user-prompt path, `route_model()` returns a `ModelRoutingDecision` with `reason_code='classifier_invalid'` and `routed_model=requested` (fail-closed, original model preserved). No blend is computed. This is asymmetric with the system-prompt fail-open by design: the user-prompt score is the primary signal; without it there is nothing to blend.

2. **Token budget:** `_CLASSIFIER_MAX_TOKENS` is raised from 4 to 8 to accommodate "100" plus any trailing whitespace or newline the model may emit. The confidence-bump path retains its own `_CLASSIFIER_MAX_TOKENS_JSON = 40` budget.

3. **Confidence-bump mode:** When `auto_model_routing_confidence_bump` is True, the JSON format switches from `{"label":"standard","confidence":0.87}` to `{"score":42,"confidence":0.87}`. `parse_classifier_label_json` is renamed to `parse_classifier_score_json` and updated to read `score` (integer, 0–100) instead of `label`. Out-of-range `score` values (e.g., `150`) are rejected — `parse_classifier_score_json` returns `None`. The one-number plain path is unaffected when confidence bump is off.

4. **Weighted blend:** The blend arithmetic `sys_weight × sys_score + user_weight × user_score` (ADR 0010) now operates directly on 0–100 integers, producing a 0–100 weighted result. The `_LABEL_SCORES` dict is removed.

5. **Tier thresholds:** `auto_model_routing_trivial_threshold` and `auto_model_routing_standard_threshold` are rescaled from the 0–2 range to 0–100. New defaults: `trivial_threshold=38`, `standard_threshold=75`. These are the exact equivalents of the prior 0.75/1.50 on the 0–2 scale (rounded), and preserve prior routing behavior for default-config operators. Any intentional policy shift in routing aggressiveness belongs in a separate decision. Both remain operator-configurable in `config.py`. Startup validation continues to assert `trivial_threshold < standard_threshold`.

6. **Tier derivation from score:** The label (`trivial`/`standard`/`deep`) is derived from the numeric score by applying the thresholds after blending: `score < trivial_threshold → 'trivial'`; `score < standard_threshold → 'standard'`; else `'deep'`. Both `system_prompt_score` (raw 0–100 float from the classifier) and `system_prompt_tier` (derived label) are preserved in `ModelRoutingDecision` for telemetry and backward compatibility with DB consumers. For the user-prompt path: `user_prompt_score` stores the raw 0–100 value and `user_prompt_tier` stores the derived tier label (`trivial`/`standard`/`deep`). This makes both paths symmetric: `user_prompt_score`/`user_prompt_tier` mirror `system_prompt_score`/`system_prompt_tier`.

7. **System-prompt cache:** The LRU cache changes from `sha256 → (label_str, float)` to `sha256 → float` (the raw 0–100 score). The label is derived on each cache read by applying thresholds, rather than stored alongside the score. Failed classifications are still not cached. When `parse_classifier_score()` returns `None` for the system-prompt classifier call, `_classify_system_prompt()` treats it as a failed classification: it returns `(trivial_threshold + standard_threshold) / 2` (a threshold-safe midpoint that always lies in the standard band) and sets `sys_failed=True`, matching the existing fail-open behavior; the result is not written to cache. Using a fixed `score=50` would be unsafe: if an operator sets `trivial_threshold=60`, a score of 50 would route to trivial; the midpoint is guaranteed to lie in the standard band regardless of operator-configured thresholds. When `system_preview` is empty (no system prompt present), `_classify_system_prompt()` returns the same threshold-safe midpoint `(trivial_threshold + standard_threshold) / 2` with `sys_failed=False`, treating absence as a neutral standard-tier signal.

8. **`classification` field:** `ModelRoutingDecision.classification` continues to store the derived tier label (e.g., `'standard'`) when an LLM classifier call succeeds. Raw score is in `user_prompt_score`. It remains `None` on all other paths (rules, tag, size floor, affirmation-inherited, failed, invalid). This preserves backward compatibility with existing DB consumers reading `classification` as a label string.

9. **Reason codes:** `classifier_trivial` / `classifier_standard` / `classifier_deep` are retained, derived from the bucketed tier after thresholding. They describe routing outcome, not raw classifier output, so the naming remains meaningful. Explicit score→reason-code mapping: `score < trivial_threshold → 'classifier_trivial'`; `score < standard_threshold → 'classifier_standard'`; else `'classifier_deep'`. This mapping applies uniformly to both user-prompt and system-prompt paths (via `user_prompt_tier` / `system_prompt_tier`) after thresholding. It is a deterministic bijection derived from the configured thresholds.

10. **Logging:** Log format becomes `score=42 (tier=deep)` for both user-prompt and system-prompt classifier calls. No change to log levels or log-line positions.

11. **Rules mode:** Unchanged. `classify_by_rules()` continues to return `'trivial'`/`'standard'`/`'deep'` or `None`. It bypasses the weighted blend entirely and maps directly to a tier via `config.auto_model_routing_classification`.

12. **`_cap_cached_tier`:** Unchanged. It operates on tier strings (model names) and uses `model_tier_rank()` for comparisons; it never touches classifier labels or scores.

13. **Migration:** Big bang. SessionDB tier caches (haiku/sonnet/opus strings) are unaffected. Default threshold values change from 0.75/1.50 (0–2 scale) to 38/75 (0–100 scale), preserving prior routing behavior for default-config operators. Operators with customised threshold values must rescale them manually; no automatic migration is provided. Pre-existing `classification` column rows contain tier label strings (`'trivial'`/`'standard'`/`'deep'`). Since `classification` continues to store the derived tier label after this change, no format distinction is needed — old and new rows are both label strings; no consumer migration required for the `classification` column itself. `parse_classifier_label_json` is renamed to `parse_classifier_score_json`; any out-of-tree callers must update their references.
