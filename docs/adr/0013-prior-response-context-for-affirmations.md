# Inject prior assistant response into classifier input for short affirmations

When the user sends a bare affirmation ("yes", "go ahead", "proceed"), the existing code in `route_model()` inherits the cached session tier or floors to standard — it does not call the classifier. The invariant in `docs/agents/model-routing.md` states: "Short direct user affirmations inherit the cached tier when available; without one they use the configured floor. They must not overwrite the tier cache."

**This ADR amends that invariant** for the no-cache case. The affirmation-handling code path is modified to call the classifier *only when no cached tier exists*. When a cached tier is available, the existing early-return path (inherit without calling the classifier) is preserved unchanged. When no cache exists, the affirmation code path calls the classifier with enriched input (see below) to establish a tier for this turn and subsequent tool turns. If prior-response enrichment is unavailable (no text blocks in the prior assistant message), the classifier receives just the affirmation text and classifies it as trivial; that tier is still written to the cache, ensuring deterministic session routing.

We add a `prior_response_summary` field to the classifier JSON, injected only when `is_short_affirmation()` is true AND the classifier is about to fire (no cached tier available). The user-prompt classifier system prompt (`_CLASSIFIER_SYSTEM_JSON`) must be amended to accept and prioritize `prior_response_summary` when present: append "When prior_response_summary is provided, judge complexity from the context in prior_response_summary; it describes what the user is agreeing to proceed with." This ensures that the enriched context is not silently discarded.

**System prompt and parser selection:** The affirmation-enriched classifier call uses the same system-prompt and parser logic as the normal (non-affirmation) routing path. When `config.auto_model_routing_confidence_bump` is True, use `_CLASSIFIER_SYSTEM_JSON` and parse structured JSON output (with confidence score extraction). When False, use `_CLASSIFIER_SYSTEM` and parse the one-word label. Do **not** override the `confidence_bump` flag for affirmation calls — this ensures the prompt/parser pair remains consistent and the label output format matches the parser expectation. Prior-response enrichment (the `prior_response_summary` field) is passed to the classifier regardless of which prompt is used; the system prompt amendment in `_CLASSIFIER_SYSTEM_JSON` informs the JSON-mode classifier to prioritize prior context when present.

The summary is extracted by walking backward through `payload['messages']` to find the most recent `role='assistant'` message that contains text content. The extraction process:
1. Walk backward through messages, skipping non-dicts and messages not having `role='assistant'`.
2. For each assistant message, check if `content` is a `str`: if so, collect it. If `content` is a list, iterate and collect text from blocks where `type == 'text'` (skip `tool_use`, `thinking`, `tool_result`, `image`, and any other block types), concatenating with `'\n'` to preserve block boundaries. If the assistant message dict lacks a `content` key or content is `None`, or if no text blocks are found, continue walking backward to the next assistant message.
3. Return the first non-empty text collected; if no text is found in any assistant message, do not inject `prior_response_summary` and classify the bare affirmation only.

**Critical invariant:** Do not classify bare affirmation text when no prior assistant message with text content exists. This prevents the "Classify with just the affirmation text" scenario (rejected in Considered Options) from activating when the client omits history or when the last assistant turn contained only tool-use blocks. When the backward walk finds no text-bearing assistant message, use the floor tier without calling the classifier; return `classification=None` so no tier cache entry is created.

**Truncation strategy (30/70 head/tail split):** When the extracted text exceeds the configured limit, apply a head/tail pattern: `head_len = int(limit * 0.30)`, `tail_len = limit - head_len - len(_TRUNCATION_MARKER)`, joined with `_TRUNCATION_MARKER` (`'\n...[truncated]...\n'`). Apply capping during extraction: for plain strings slice directly; for list extraction use a rolling tail buffer (O(limit) memory). The head (30%) preserves the task preamble; the tail (70%) preserves the final state. When the full text fits within the limit, return it whole without a separator.

The classifier result on the affirmation path DOES write to the tier cache **when classification succeeds**. Because this code path fires only when no cached tier exists, there is no established tier to overwrite — the successful result creates the first cache entry for this context key. The cache key must be the composite context key mandated by model-routing.md: `(session ID, stable first-user-message hash)`, NOT the bare session key. This ensures subsequent tool-call turns within the same session read from the same cache entry, allowing them to inherit the established tier without re-classifying. **If the classifier call fails** (network error, invalid response), the floor tier is used for this affirmation turn only; the tier cache remains empty, so the next non-affirmation turn in the session will attempt classification normally.

**Interaction with ADR 0010 (weighted combination):** the weighted system-prompt + user-prompt blend (ADR 0010) applies to all classifier calls, including affirmation turns. When `is_short_affirmation()` fires without a cached tier and the classifier is invoked with `prior_response_summary`, the resulting user-prompt score feeds into the same weighted formula. Order of operations: (1) check for cached tier; if found, inherit and exit (model-routing.md invariant preserved); (2) obtain `system_prompt_score` by consulting the LRU cache (if cache miss, dispatch isolated classifier call, fallback to 1.0 on failure); (3) inject prior response if available, (4) classify user prompt → user_score, (5) blend system_prompt_score and user_score using configured weights, (6) threshold → final tier. The final blended tier is written to the tier cache. Steps 2 and 3–4 have no data dependencies and may be dispatched concurrently when an isolated classifier transport layer supports concurrent calls (see implementation notes).

## Considered Options

**Inherit cached tier only (status quo):** Correct when a relevant tier is cached, wrong otherwise. Doesn't handle sessions where the affirmation kicks off work that differs from prior complexity.

**Read last response from DB (`response_text`):** More reliable across client implementations, but adds a DB read per affirmation turn. Rejected in favour of reading from `payload['messages']`, which is always in-process. DB fallback can be added later if needed.

**Classify with just the affirmation text:** Routes to trivial/haiku every time. Poisons the tier cache for follow-on tool turns. Rejected.

**Gate enrichment on `confidence_bump`:** Would reuse the existing JSON-mode flag. Rejected because `confidence_bump` defaults to False, which would silently disable enrichment for most deployments without any indication.

**Head-cap only (first N chars):** Discards the tail of the prior assistant response, which carries the final state and conclusion — high-signal for complexity. Rejected in favour of the 30/70 head/tail split.

## Consequences

- `prior_response_summary` is NOT added to `RoutingSummary`. Instead, `to_classifier_json()` gains a `prior_response_summary: str | None = None` parameter; when non-None, the field is merged into the routing-summary dict before `json.dumps()`. This eliminates the need for a general `extra_fields` mechanism and its key-collision guard.
- `ModelRoutingDecision` gains a `cache_tier: str | None = None` field. For the `affirmation_classified` path, `routed_model` holds the capped tier (for this turn's dispatch) and `cache_tier` holds the uncapped resolved tier model (`config.auto_model_routing_classification[label]`). `handlers.py` must explicitly check the reason code: for `affirmation_classified`, write `routing.cache_tier or routing.routed_model` (uncapped) to the tier cache; for all other successful routes (`classification is not None`), write `routing.routed_model` as before (the cache_tier field is None on all non-affirmation paths, preserving existing behavior).
- Two new reason codes: `affirmation_classified` (no cache, classifier succeeded, result written to tier cache) and `affirmation_classifier_failed` (classifier error, floor used, cache remains empty). `affirmation_floored_standard` is retired from the affirmation code path; its existing uses in non-affirmation floor scenarios are unaffected.
- `admin.py`'s `affirmation_count` KPI set must be updated to include `affirmation_classified` and `affirmation_classifier_failed` alongside the existing codes. `affirmation_floored_standard` is retained in the set to handle old stats rows across the migration boundary.
- New config: `auto_model_routing_prior_response_summary_limit` (int, default 1000). Startup validation must assert `50 <= value <= 32_000`; raise `ValueError` if violated. The lower bound of 50 ensures the 30/70 head/tail split formula (`tail_len = limit - int(limit*0.30) - len(_TRUNCATION_MARKER)`) produces non-negative tail_len (at 50: head=15, tail=50-15-19=16 ✓; at 28: head=8, tail=28-8-19=1 ✓; below 28 tail becomes negative, causing runtime errors). An upper bound of 32,000 guards against excessively large classifier payloads. The feature is disabled by setting `auto_model_routing_affirmation_inherit = false`, not by adjusting the limit.
- The affirmation code path in `route_model()` is restructured: check for cached tier first; if found, inherit and return early. Only when no cache exists, call the classifier (always using `_CLASSIFIER_SYSTEM_JSON`) with enriched input.
- Text extraction handles two content forms: plain string (use directly) and list (collect `type='text'` blocks, skip all others, concatenate with `'\n'`). Defensive `isinstance(element, dict)` check before accessing block fields, using `element.get('text') or ''` to handle missing keys, prevents AttributeError on malformed content. 30/70 head/tail split applied during extraction: when content is a plain string, it is already in memory and sliced directly; when content is a list, use a rolling tail buffer (O(limit) memory) to avoid unnecessary full allocation when messages are large.
- Latency: affirmation turns with a cached tier incur no additional latency. Affirmation turns with no cached tier add one classifier round-trip. All other turn types are unaffected.
- **Validation:** startup config validation must assert `50 <= auto_model_routing_prior_response_summary_limit <= 32_000`; raise `ValueError` with readable text if violated. The minimum of 50 is a practical floor that ensures a reasonable extraction window; the formula's arithmetic minimum is 29, but 50 is conservative to leave headroom for typical message structures.
- **Concurrent affirmation misses:** when two simultaneous affirmations on the same session both read an empty cache, both invoke the classifier independently and both attempt to write the tier cache. To mitigate TOCTOU races, the implementation must use a per-ctx_key in-flight sentinel: before dispatching the classifier, set a sentinel at `ctx_key` (e.g., a sentinel string or a dedicated "in-flight" marker distinct from a cached tier). If the sentinel is already present, skip the classifier call and use the floor tier instead (another concurrent call is already in progress). After the classifier returns, clear the sentinel and write the result. This coalesces concurrent affirmation calls on the same context key so only one classifier call succeeds and writes to the cache.
- **Tier cache write wiring:** handlers.py's tier-cache write for `classification is not None` must explicitly distinguish the new `affirmation_classified` reason code. For this code, write `routing.cache_tier or routing.routed_model` (uncapped tier to cache). For all other paths, write `routing.routed_model` as before (or verify that `routing.cache_tier` remains `None` so the `or` short-circuits to the existing behavior). This ensures affirmation-classified tiers are cached uncapped so downstream turns apply their own capping, while non-affirmation tiers are cached as-routed (already capped).
- Requires `payload['messages']` to contain the full conversation history. Claude Code always sends it; other clients may not — the field is `None` and the classifier receives just the affirmation text.
- **Edge case — no prior text-bearing assistant message (session-opening affirmation, client history pruning, tool-use-only prior turn):** When the backward walk through `payload['messages']` finds no assistant message with text content, the no-cache affirmation path does **not** classify the bare affirmation. Instead, it uses the floor tier (standard) for this turn and returns `classification=None`, preventing a tier cache entry from being created. This preserves the critical invariant: "Do not classify bare affirmation text when no prior text context exists." Subsequent non-affirmation turns in the same session (e.g., a tool-result continuation) will attempt classification normally and establish a tier if successful. This is the guard against the "Classify with just the affirmation text" scenario rejected in Considered Options.
- **`ctx_key=None` gate:** Sessions without `metadata.user_id` produce a `None` context key; the cache write is skipped (handlers.py line 725 gate) even when classification succeeds. Such sessions receive correct per-turn routing but do not persist a tier for downstream turns.
- **Updated model-routing.md invariant:** "Short direct user affirmations inherit the cached tier when available; without one, call the classifier — with prior-response context if available, otherwise with the bare affirmation text — and write the result to the tier cache to serve subsequent turns. Fall back to the configured floor only when the classifier call itself fails." **Implementation scope includes propagating this revised invariant to `docs/agents/model-routing.md`.**
